# 투영 경계 안티에일리어싱

BS24 출력 코어는 정이십면체 타일 색상 조회와 RGB FIFO 사이에 경계 적응형
안티에일리어싱 단계를 둔다. 이 단계는 창 합성 소프트웨어가 만든 장면을 바꾸지
않고 최종 투영 결과에 적용된다.

필터는 현재 픽셀과 바로 왼쪽·윗쪽 원본 픽셀의 근사 밝기 차이를 계산한다.
설정된 임계값을 넘는 방향 중 차이가 더 큰 방향의 이웃을 선택하고, 현재 색상을
설정 강도만큼 이웃 색상 쪽으로 혼합한다. 경계가 아닌 픽셀과 첫 행·첫 열은
그대로 통과한다. 이전 출력이 아니라 원본 투영 색상을 줄 버퍼에 저장하므로
재귀적으로 흐려지지 않는다.

```text
타일 색상 ─┬─ 현재 밝기 ─┐
            ├─ 왼쪽 밝기 ─┼─ 최대 경계 방향 ─ 색상 혼합 ─ RGB FIFO
한 줄 버퍼 ┴─ 위쪽 밝기 ─┘
```

구현은 분산 RAM으로 합성되는 한 개의 1280×24비트 줄 버퍼와 4단 연산
파이프라인을 사용한다. 첫 결과의 지연은 4클록이고 이후 입력과 출력은 모두
1픽셀/클록이며 픽셀 개수와 순서를 유지한다. 2×2 MSAA처럼 투영기나 장면 캐시
읽기를 복제하지 않는다.

## 설정

AXI-Lite `0x1c` 레지스터 형식은 다음과 같다.

| 비트 | 이름 | 설명 |
|---:|---|---|
| 0 | enable | 1이면 AA 적용 |
| 15:8 | threshold | 밝기 차이 임계값, 0~255 |
| 23:16 | strength | 이웃 색상 혼합량, 0~255 |

초기값은 `enable=1`, `threshold=24`, `strength=32`다. 강도 32는 약 12.5% 혼합을
의미한다.

```python
driver.set_antialias(True, threshold=24, strength=32)

with BosioWMClient("settings") as client:
    client.set_antialias(True, threshold=24, strength=32)
```

임계값을 낮추면 더 많은 경계에 적용되고, 강도를 높이면 계단은 부드러워지지만
작은 글자와 세밀한 무늬가 흐려질 수 있다. 비교할 때는 `enabled=False`로 끈
영상과 같은 자세에서 확인하는 것이 좋다.

## 현재 제한

- 한쪽 방향의 과거 픽셀만 사용하는 인과 필터이므로 대칭 3×3 필터보다 품질은
  낮지만 프레임 끝 플러시와 추가 두 줄 버퍼가 필요 없다.
- 색상 차이로 경계를 찾으므로 의도적인 고주파 무늬에도 적용될 수 있다.
- 이 단계는 장면 생성 시의 텍스처 축소 필터를 대신하지 않는다.

## 투영 소프트웨어 AA

창 표면을 구면 셀에 매핑할 때 네이티브 합성기는 셀 중심을 bilinear 보간한다.
기존 4×4 AA는 이미지 좌표에서 고정된 약 1픽셀만 평균하여, `M=16` 셀이 실제로
여러 이미지 픽셀을 덮는 창에서는 얇은 획을 놓칠 수 있었다. 현재는 각 셀 중심과
인접한 삼각 셀 중심의 방향을 창 표면으로 투영하여, 이미지 좌표에서 셀의 가로·세로
샘플 반경을 구한다. 반경은 이미지 좌표에서 0.5~6픽셀로 제한한다.

반경이 작은 셀은 bilinear 중심 샘플, 일반 셀은 반경에 맞춘 2×2 평균을 사용한다.
셀 안의 3×3 밝기·색상 검사에서 경계가 발견되면 4×4 평균으로 확장한다. 매우 얇은
어두운 획이 면적 평균으로 지나치게 옅어지지 않도록 강한 밝기 대비에서는 부분
커버리지를 소폭 보정한다. 평균과 대비 보정은
RGB332로 양자화하기 전에 수행한다. 창 제목과 테두리 오버레이는 이 평균을
거치지 않고 기존 색상을 유지한다. NumPy fallback도 동일한 셀 반경 기반 샘플
위치를 사용한다.
RGB332 팔레트에서 같은 R/G 양자화 레벨을 가진 회색 8개 항목은 RGB 채널이
같은 중립 회색으로 지정한다. 따라서 검정 글자의 부분 커버리지 결과가 청색이나
황색으로 번져 보이지 않는다. 나머지 팔레트 항목과 8비트 셀 인덱스 형식은 유지한다.

소스 표면의 일부만 바뀌면 셀별 AA 샘플 반경과 겹치는 셀만 dirty tile로
재합성한다. 따라서 전체 장면을 다시 투영하지 않고도 소프트웨어 AA 품질을 유지한다.
기본값은 켜짐이며, A/B 비교나 성능 측정에서는 `SphericalWindowManager(...,
projection_aa=False)`로 끌 수 있다. 보드 데몬은 네이티브 합성기를 사용하므로 이
설정이 실제 HDMI 출력 경로에 적용된다.

`verification/test_projection_aa.py`는 `M=16`에서 2픽셀 획의 중간 색 생성과
AA 반경 안에 들어오는 dirty 셀 누락 방지를 검사한다.
`verification/benchmark_projection_aa.py`는 같은 장면의 AA off/on 획 커버리지와
부분 갱신 시간을 비교한다. 개발 PC의 네이티브 C++ 빌드에서 수직 획 장면의
중간 밝기 셀은 AA off 0개, AA on 3,828개였고, 작은 획의 갱신은 양쪽 모두
BPT1 patch로 유지되었다. 로컬 부분 갱신 중앙값은 약 0.1ms였으며, 이 값은
PYNQ-Z2의 Cortex-A9 처리량을 나타내지 않는다.
보드의 `sw/install_bosio_boot.sh`는 설치할 때 ARM용 네이티브 라이브러리를 현재
C++ 소스에서 다시 빌드한 뒤 데몬을 재시작한다. 저장소에 포함된 이전 `.so`만
복사하면 이 투영 변경이 HDMI에 반영되지 않는다.

소프트웨어 투영 AA와 BS24 출력 코어 AA를 함께 켜면 투영 샘플링과 최종 경계 필터가
각각 다른 단계에서 동작한다. 기본 BS24 혼합 강도는 이중 블러를 줄이기 위해 64에서
32로 낮췄다. 선명도가 중요하면 소프트웨어 AA만, 얇은 고대비 경계의 잔여 계단까지
줄이려면 두 단계를 함께 사용한다.

남은 화질 제한은 각 삼각 셀이 최종적으로 한 개의 8비트 팔레트 색만 갖는다는
점이다. AA는 셀 안의 색을 평균할 수 있지만 셀 수와 팔레트 색 수를 늘리지는
않는다. 실제 글꼴·아이콘의 가독성은 같은 자세에서 캡처보드 A/B 영상으로
추가 확인해야 한다.

## PYNQ-Z2 검증 결과

Vivado 2020.2의 전체 배치·배선 결과는 setup WNS `+0.281 ns`, hold WHS
`+0.051 ns`이며 위반 endpoint는 0개다. 전체 시스템 자원 사용량은 LUT
26,894개(50.55%), 레지스터 24,710개(23.22%), BRAM tile 137.5개(98.21%),
DSP 83개(37.73%)다.

실물 PYNQ-Z2에서 BS24 bitstream을 내려받아 장면 출력, GY-521 자세 스트림,
AA off/on 레지스터 readback을 확인했다. 2초간 하드웨어 frame counter로 측정한
출력은 60 FPS였고, USB3.0 Video 캡처보드에서 1920×1080 입력 프레임을
수신했다.
