# 투영 경계 안티에일리어싱

BS24 출력 코어는 정이십면체 타일 색상 조회와 RGB FIFO 사이에 경계 적응형
안티에일리어싱 단계를 둔다. 이 단계는 창 합성 소프트웨어가 만든 장면을 바꾸지
않고 최종 투영 결과에 적용된다.

필터는 현재 픽셀과 바로 왼쪽·윗쪽 원본 픽셀의 근사 밝기 차이를 계산한다.
설정된 임계값을 넘는 방향 중 차이가 더 큰 방향의 이웃을 선택하고, 현재 색상을
설정 강도만큼 이웃 색상 쪽으로 혼합한다. 경계가 아닌 픽셀과 첫 행·첫 열은
그대로 통과한다. 이전 출력이 아니라 원본 투영 색상을 줄 버퍼에 저장하므로
재귀적으로 흐려지지 않는다.

```text
타일 색상 ─┬─ 현재 밝기 ─┐
            ├─ 왼쪽 밝기 ─┼─ 최대 경계 방향 ─ 색상 혼합 ─ RGB FIFO
한 줄 버퍼 ┴─ 위쪽 밝기 ─┘
```

구현은 분산 RAM으로 합성되는 한 개의 1280×24비트 줄 버퍼와 4단 연산
파이프라인을 사용한다. 첫 결과의 지연은 4클록이고 이후 입력과 출력은 모두
1픽셀/클록이며 픽셀 개수와 순서를 유지한다. 2×2 MSAA처럼 투영기나 장면 캐시
읽기를 복제하지 않는다.

## 설정

AXI-Lite `0x1c` 레지스터 형식은 다음과 같다.

| 비트 | 이름 | 설명 |
|---:|---|---|
| 0 | enable | 1이면 AA 적용 |
| 15:8 | threshold | 밝기 차이 임계값, 0~255 |
| 23:16 | strength | 이웃 색상 혼합량, 0~255 |

초기값은 `enable=1`, `threshold=24`, `strength=64`다. 강도 64는 약 25% 혼합을
의미한다.

```python
driver.set_antialias(True, threshold=24, strength=64)

with BosioWMClient("settings") as client:
    client.set_antialias(True, threshold=24, strength=64)
```

임계값을 낮추면 더 많은 경계에 적용되고, 강도를 높이면 계단은 부드러워지지만
작은 글자와 세밀한 무늬가 흐려질 수 있다. 비교할 때는 `enabled=False`로 끈
영상과 같은 자세에서 확인하는 것이 좋다.

## 현재 제한

- 한쪽 방향의 과거 픽셀만 사용하는 인과 필터이므로 대칭 3×3 필터보다 품질은
  낮지만 프레임 끝 플러시와 추가 두 줄 버퍼가 필요 없다.
- 색상 차이로 경계를 찾으므로 의도적인 고주파 무늬에도 적용될 수 있다.
- 이 단계는 장면 생성 시의 텍스처 축소 필터를 대신하지 않는다.

## 투영 소프트웨어 AA

창 표면을 구면 셀에 매핑할 때 네이티브 합성기는 모든 출력 셀을 부동소수점 투영
좌표에서 bilinear 보간한다. 중심을 둘러싼 네 픽셀의 명암 범위가 임계값을 넘는
고대비 셀에는 4×4 supersampling을 추가 적용한다. 평균은 RGB332로 양자화하기 전에
수행하므로 글자 획과 모서리가 셀 중심에 걸쳐 있을 때 계단 현상이 줄어든다. 창
제목과 테두리 오버레이는 이 평균을 거치지 않고 기존 색상을 유지한다.

소스 표면의 일부만 바뀌면 bilinear/4×4 샘플 영역과 겹치는 셀만 dirty tile로
재합성한다. 따라서 전체 장면을 다시 투영하지 않고도 소프트웨어 AA 품질을 유지한다.
기본값은 켜짐이며, A/B 비교나 성능 측정에서는 `SphericalWindowManager(...,
projection_aa=False)`로 끌 수 있다. 보드 데몬은 네이티브 합성기를 사용하므로 이
설정이 실제 HDMI 출력 경로에 적용된다.

소프트웨어 투영 AA와 BS24 출력 코어 AA를 함께 켜면 투영 샘플링과 최종 경계 필터가
각각 다른 단계에서 동작한다. 기본 BS24 혼합 강도는 이중 블러를 줄이기 위해 64에서
32로 낮췄다. 선명도가 중요하면 소프트웨어 AA만, 얇은 고대비 경계의 잔여 계단까지
줄이려면 두 단계를 함께 사용한다.

## PYNQ-Z2 검증 결과

Vivado 2020.2의 전체 배치·배선 결과는 setup WNS `+0.281 ns`, hold WHS
`+0.051 ns`이며 위반 endpoint는 0개다. 전체 시스템 자원 사용량은 LUT
26,894개(50.55%), 레지스터 24,710개(23.22%), BRAM tile 137.5개(98.21%),
DSP 83개(37.73%)다.

실물 PYNQ-Z2에서 BS24 bitstream을 내려받아 장면 출력, GY-521 자세 스트림,
AA off/on 레지스터 readback을 확인했다. 2초간 하드웨어 frame counter로 측정한
출력은 60 FPS였고, USB3.0 Video 캡처보드에서 1920×1080 입력 프레임을
수신했다.
