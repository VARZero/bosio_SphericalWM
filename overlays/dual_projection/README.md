# M=32 output + two projection engines

The deployed SW-HW runtime caches projected window tiles, projects only changed
source tiles, reuses unchanged overlapping windows, and submits changed output
tiles. No visual change means zero projection jobs and no output commit.
See [measurements](INCREMENTAL_RESULTS.md) and [contract](AGENTS.md).

## Separate IPs

- Output RTL: `../../hw/ip_repo/bosio_output_core_1.0` (OutputCore submodule).
- Projection HLS/model/scheduler: `../../hw/ip_repo/bosio_projection_core`
  (ProjectionCore submodule).
- This folder: dual-engine block design, routed bit/HWH, deployed Python runtime,
  window/tile caches and validation. Output driver and projection scheduler load
  directly from their respective submodules; geometry remains the WM version.

Output: 0x43c00000/HP0; projector0: 0x43c10000/HP1; projector1: 0x43c20000/HP2.
100 MHz, native AXI masters, no added AXI DMA IP. The validated bitstream is unchanged.

## Launch and test

Initialize dependencies with `git submodule update --init --recursive`.
Host: `python overlays/dual_projection/run.py --script test_incremental.py`.
On PYNQ, build native fallback with `sw/native/build_pynq.sh`. Stop the existing
WM service before using PYNQ Python to launch:
`sudo -E python3 overlays/dual_projection/run.py` (XILINX_XRT=/usr as needed).
The launcher chooses M=32, bundled dual bitstream, and 30 Hz update limit.
The legacy default daemon/service is preserved. Clients use /tmp/bosio-wm.sock.
Do not run standalone projection tests while the compositor owns the engines.

To show the current color-block test window at the sensor view, keep
`run.py --script show_preview_window.py` running; Ctrl+C closes it.

While running, `run.py --script validate_incremental.py` checks real changes,
reuse and full 4,220-tile reference equality. `check_display_health.py` checks
output progress. `validate_display_pose.py` temporarily centers the view and
restores sensor tracking; use the privileged PYNQ environment for that script.

## Build

Run Vitis HLS 2022.2 on the projection submodule's `scripts/build_hls.tcl`, then
Vivado 2022.2 on this folder's `scripts/build.tcl`. Supply Digilent rgb2dvi:1.4
under WM hw/ip_repo as described in its README. WM provides sensor IP and HDMI
constraints. Timing and HDMI physical checks gate bitstream export.

13 host tests and 14 board cases passed before publication. Results are historical
measurements, not regenerated by copying files; source paths refer to the original
workspace. Packaging/launch paths are checked on the host without restarting the
currently displayed board runtime.

## BoAYO rounded windows

The PS now caches rounded-rectangle shape coverage while FPGA engines project
content tiles. Shape-only changes reuse projected pixels. See
[BoAYO M32 results](BOAYO_M32_RESULTS.md) for SDK delta uploads, chrome caching
and actual Dashboard validation. Decorated/unsupported-size windows retain native fallback.
