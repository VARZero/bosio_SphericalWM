# M=32 Output Core + 투영코어 2개 실측

2026-10-17, PYNQ-Z2에서 생성·배포·메모리 검증 완료.

이 문서는 독립 메모리 검증 당시 결과다. 이후 실제 화면 연결까지 완료했으며,
현재 실행 상태와 화면 검증 결과는 `DISPLAY_RESULTS.md`에 기록했다.

한 비트스트림에 BS25 Output Core M=32와 100 MHz 투영코어 2개를 배치했다.
출력은 HP0, 투영 0은 HP1, 투영 1은 HP2로 DDR에 접근한다. 제어 주소는
각각 `0x43C00000`, `0x43C10000`, `0x43C20000`이다. 추가 AXI DMA IP 없이
각 코어의 기존 AXI master를 사용한다. HP 포트는 물리 DDR 컨트롤러를 공유한다.

## SW–HW Co-Design

PS가 컬링과 descriptor 생성을 담당하고 목적지 타일 단위로 두 큐에 분배한다.
동일 타일의 모든 레이어는 원래 순서대로 한 코어에서 처리한다. 다른 타일은
동시에 처리하며, 부분적으로 겹치는 목적지 범위는 실행 전에 거부한다.
입력 텍스처는 읽기 전용으로 공유하고 각 코어의 descriptor 버퍼는 분리했다.

드라이버는 실행 전 cache flush, 두 코어 시작, 양쪽 완료 대기, 실행 후
invalidate를 수행한다. 완료 전에는 버퍼를 해제하지 않는다. 메모리 검증은
현재 출력 장면과 분리된 DDR 버퍼에서 실행했다.

## 실제 FPGA 사용량

출력·HDMI·센서·버튼·AXI 연결을 포함한 배치·배선 결과다.

| 자원 | 사용량 | 디바이스 대비 | 기존 투영 1개 구성 대비 증가 |
|---|---:|---:|---:|
| LUT | 32,135 / 53,200 | 60.40% | +3,912 |
| FF | 37,644 / 106,400 | 35.38% | +6,448 |
| BRAM, 36Kb 환산 | 27.5 / 140 | 19.64% | +2.5 |
| DSP48 | 155 / 220 | 70.45% | +36 |

추가된 투영 IP 자체는 LUT 3,223, FF 5,457, BRAM 2.5, DSP 36개다.
전체 증가량에는 AXI 연결 등의 변화도 포함된다. 점유 Slice는 11,861/13,300
(89.18%)이므로 LUT 비율만으로 배치 여유를 판단하면 안 된다.

최종 setup WNS **+0.073ns**, hold WHS **+0.049ns**, pulse width 여유
**+0.540ns**. 세 bus-skew 검사의 최소 여유는 **+8.275ns**다.
HDMI 8개 핀과 4개 차동 출력 버퍼를 확인했다. 100 MHz에서 통과했지만
setup 여유가 작으므로 이후 구조·클럭 변경은 다시 배치·배선해 확인해야 한다.

Clock Wizard의 중복 primary clock 및 해당 jitter 두 줄을 제거하고 실제
PS FCLK0의 0.300ns jitter를 유지한 동일 배선 결과의 보고서다. 그 외 기존
timing/CDC 제약은 보존했다. DRC error/critical warning은 없고 일반 경고
361건이 남아 있다. Methodology도 critical warning은 없으나 일반 경고 247건이
있으며, 비동기 reset, I/O delay 누락, 기존 출력/영상 clock-group의 max-delay
우선순위 경고 등이 포함된다. 따라서 제약에 따른 timing 통과와 보드 기능 검증을
확인한 것이며, 모든 외부 인터페이스의 타이밍 검증까지 완료했다는 뜻은 아니다.

## 같은 장면의 1개 대 2개 비교

동일한 새 비트스트림·버퍼·입력에서 `workers=1`과 `workers=2`를 번갈아
각 3회 실행한 중앙값이다. SW 컬링 후 511타일, 샘플링 셀 463,910개이며
두 코어에는 256/255타일을 분배했다. 모든 결과는 CPU 기준값과 일치했다.

| 측정 범위 | 투영 1개 | 투영 2개 | 속도 향상 |
|---|---:|---:|---:|
| 시작부터 완료 polling까지 | 593.57ms | 300.73ms | 1.97배 |
| PS 드라이버 전체 호출 | 635.14ms | 367.21ms | 1.73배 |

전체 호출에는 큐 분배·descriptor 준비·cache 처리·레지스터 설정·descriptor
무결성 검사가 포함된다. CPU 기준값 계산, 호출자의 장면 초기화, 출력 장면으로
넘기는 작업은 포함하지 않는다. 실사용 드라이버가 처리하는 데이터량과 검증
옵션에 따라 PS 비용은 달라질 수 있다.

별도의 전체 구면 4,220타일 병렬 실행은 **386.31ms**였고, 컬링한 동일 장면은
**302.17ms**였다. 두 경우 전체 목적지 DDR 내용이 동일했다. 출력 프레임 증가량은
드라이버 준비와 반환까지 포함한 구간에서 측정하므로 이 숫자를 투영 시간으로
나누어 출력 FPS를 계산해서는 안 된다.

## 검증 및 적용 범위

- 각 투영코어에 기존 14개 메모리 테스트를 실행: 총 28개 통과.
- 병렬 실행·반복 성능 비교·레이어 순서·빈 큐·기존 내용 보존: 12개 실행 통과.
- 40회 실행 모두 전체 목적지 비교 불일치 0, 입력 및 descriptor 보존, guard 정상.
- 부분 중첩 타일은 하드웨어 실행 전에 거부했고 양쪽 idle을 확인했다.
- 호스트 분배 테스트 4개 통과: 순서, 소유권 분리, 빈 큐, 부분 중첩/최대 크기.
- M=32 출력이 활성화된 상태에서 실행했으며 출력 오류는 없었다.
- 검사 종료 후 양쪽 투영코어 idle, M=32 유지, 출력 3.002초간 180프레임
  (59.96fps)을 확인했다. WM·BoAYO 서비스는 active, 재시작 횟수는 각각 0이다.

보드 적용 경로는 `/home/xilinx/bosio_output_projection_dual_20261017/`이다.
서비스의 bit/HWH 경로를 전환하고 `--m 32`를 유지했다. 이전 서비스 설정은
`service_backup_20250507_044945/bosio-window-manager.service`에 보존했다.
백업 이름은 실제 날짜와 다른 보드 시각을 따른다. 기존 단일 투영 구성과
출력 전용·투영 전용 파일은 그대로 남아 있다.

현재 데스크톱은 기존 SW 합성기를 사용한다. 이번 완료 범위는 투영코어 2개와
M=32 출력의 동시 구동 및 투영 DDR 검증이다. 투영 결과를 화면에 표시하려면
PS의 palette/directory 구성과 프레임 경계에서 출력 버퍼를 넘기는 연결이 남아 있다.
약 60fps의 출력 스트림과 약 301ms의 투영 처리 시간은 별개의 지표다.
현재 데스크톱 장면에서 측정했으므로 DDR 최대 부하 시험 결과는 아니다.
